# ADR 0002: Adopt a Kind-backed local Kubernetes environment

## Status

Accepted

## Context

BidPoint's remote environments run Kubernetes workloads, while the repository originally left local execution undecided and excluded it from `gitops/`. The project goal is a seamless development experience with the highest practical local-to-remote parity.

Running processes directly on a developer machine or reading configuration from a mounted directory would create a different runtime and configuration path from the remote environments.

## Decision

`local` is a Kind Kubernetes cluster on a developer machine. It is an isolated environment alongside `dev`, `stage`, and `prod`, not a substitute for them.

`gitops/` owns the desired Kubernetes workload state for all four environments. It will use shared workload definitions with explicit environment overlays. `infra/` continues to own cloud infrastructure only and does not provision `local`.

The authoritative local integration path runs workloads in Kind. It includes Spring Cloud Config Server as a Kubernetes workload. Config Server uses a remote Git backend to serve the non-secret configuration owned by `config/`; services do not read configuration directly from the local checkout, mounted configuration files, or a filesystem fallback.

The local environment must keep Kubernetes resources, container images, service configuration protocol, health checks, and non-cloud dependency versions as close to remote as practical. It does not attempt to reproduce cloud-only behavior such as EKS control-plane operation, IAM, VPC networking, managed-database failover, or production data. Those differences are validated in remote `dev`.

## Consequences

- A working local environment requires Docker Desktop and Kind before workloads can run.
- A configuration change must be committed and pushed to the Git label Config Server serves before a client can consume it.
- Configuration is versioned and fetched through the same Config Server path in every environment; secrets remain outside Git and enter workloads through Secret references.
- Config Server needs a minimal bootstrap configuration for its Git backend before it can serve configuration. That bootstrap is an intentional exception because the server cannot configure its own source.
- The local GitOps reconciliation mechanism, Git-label promotion policy, local dependency set, and remote infrastructure implementation remain undecided and must be recorded before implementation.
