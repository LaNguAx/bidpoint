# ADR 0001: Adopt owner-marked artifact names

## Status

Accepted

## Context

BidPoint has separate modules for application source, backend configuration, Kubernetes deployment state, infrastructure, automation, and documentation. Environment-specific files need to make both their owner and target environment obvious without relying on their directory alone.

Spring Cloud Config normally discovers files using an application name and an active profile. The repository convention uses dots between the service, owner, and environment instead.

## Decision

Environment-specific non-source artifacts use this filename shape:

```text
<subject>.<owner>.<environment>.<extension>
```

Examples:

```text
auction-service.config.local.yml
auction-service.gitops.local.yaml
network.infra.dev.tf
deploy.github.prod.yml
```

Non-environment-specific non-source artifacts use:

```text
<subject>.<owner>.<extension>
```

The owner marker applies to `config`, `gitops`, `infra`, `.github`, and `docs`. Backend and frontend source code keep the naming conventions of their languages and frameworks. Names imposed by tools, including `README.md`, `package.json`, and `kustomization.yaml`, remain unchanged.

For a Spring Cloud Config source file named `auction-service.config.local.yml`, the service identity remains `auction-service`. Its Kubernetes bootstrap variables set `SPRING_CLOUD_CONFIG_NAME=auction-service.config.local` so that Config Server requests the dotted filename, while `SPRING_PROFILES_ACTIVE=local` retains the application's active environment profile. `SPRING_CLOUD_CONFIG_NAME` is bootstrap identity, not ordinary application behavior configuration.

## Consequences

- A file's ownership and target environment are visible from its name.
- Spring Cloud Config clients need the additional bootstrap identity variable; using only `SPRING_APPLICATION_NAME=auction-service` would look for the standard `auction-service-local.yml` name instead.
- The Git label remains a separate version-selection concern. It does not replace the environment segment in a filename.
- No existing implementation artifacts need renaming because the repository currently contains only scaffolding documentation.
